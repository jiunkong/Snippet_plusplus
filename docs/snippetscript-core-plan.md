# SnippetScript 코어 분리 계획

## 목표와 순서

언어 분석·실행을 독립적인 TypeScript ES 모듈로 분리한다. Chrome과 향후 VS Code 등의 호스트가 같은 코어를 사용한다.

1. 현재 기능 변경과 이 계획을 커밋·푸시한다.
2. 확장 버전을 2.0.0으로 올리고 모듈화를 시작한다.
3. https://github.com/jiunkong/SnippetScript 를 language-core/ Git 서브모듈로 연결한다.
4. 공용 분석기·실행기와 브라우저 어댑터를 연결한다.
5. 회귀 검증과 개발 문서를 완료한다.

기존 변경은 보존하고, 코어는 독립적인 버전·커밋 이력을 갖는다. 확장은 특정 코어 커밋을 고정한다.

## 책임 경계

코어: 템플릿·표현식·중첩 fragment 분석, AST, 타입·연산자·내장 함수, 변수 스코프·분기·반복, 스니펫 호출, SnippetTemplate/SnippetFragment, 진단·토큰·참조, 시간·재귀 제한·취소.

확장: 트리거 매칭, DOM·선택·삽입·커서·undo, Chrome API, UI, 번역, 설정·동기화·파일 관리. 호출 인수 이름을 추출하는 문법은 코어에 둔다.

## 분석 API

```ts
const analysis = analyze(source, { library });
const result: SnippetFragment = await execute(analysis, {
  variables, library, host, signal, limits,
});
```

Analysis는 불변 SnippetTemplate(AST), 토큰, 진단, 스니펫 참조를 포함한다. 범위는 원본 UTF-16 [start,end)이며 줄 연결·중첩 리터럴에서도 유지한다. 표현식도 AST로 분석하며 실행 시 다시 파싱하지 않는다. fragment(string) 같은 새 소스만 추가 분석한다.

불완전한 입력에서도 가능한 토큰·진단을 반환한다. 오류 진단은 실행을 막는다. 본문과 라이브러리 변경 시 캐시를 갱신한다. 하이라이터와 테스트 탭은 같은 분석 경로를 사용한다.

토큰 종류: 구문 구분자, 키워드, 변수, 일반 내장 함수, 난수 함수, 타입 관련 함수, 스니펫 호출, 연산자, 리스트·인덱스 구두점, fragment 구분자, 커서 구분자·마커, 정규식·플래그, bool 리터럴(true/false), null 리터럴. 문자열·숫자 전용 강조 종류는 이번에 추가하지 않는다.

코어는 색상·CSS를 전달하지 않는다. 하이라이터가 종류를 CSS 클래스에 매핑한다. 표현식·커서·트리거 영역 배경은 구조 범위로 재현한다. 오류는 진단, 줄바꿈은 렌더링 옵션이다. 색상 커스터마이징 UI는 범위 밖이다.

## 실행과 호스트

```ts
host.invoke({ name, args, sourceRange }, { signal });
```

prompt/choice/toast/copy/paste/url/domain/title은 코어가 인수를 평가하고 호스트가 기능을 수행한다. 함수 명세(이름·인수·대기 정책)를 공유한다. 미지원 기능은 호출 시 구조화된 오류를 낸다. 시각·난수·UUID·스케줄러는 주입 가능하며 표준 JS 기본 구현을 제공한다.

코어가 시간·재귀 제한과 취소를 관리한다. 사용자 응답 대기는 제외하고 클립보드 대기는 포함한다. 취소 후 재개하지 않고 호스트에도 취소 신호를 전달한다. 오류에는 코드·인수·범위·호출 경로를 제공하고 호스트가 번역한다.

&&, ||, 삼항식은 선택된 분기만 실행한다. 나머지 타입·형변환·스코프·커서·fragment 동작은 현재와 동일하다. 문자열을 암묵적으로 실행 소스로 해석하지 않는다.

## 빌드와 검증

확장의 진입점과 의존 파일을 명시적인 ES 모듈로 전환하고 esbuild로 번들링한다. npm run build는 정적 파일·번들을 dist/에 모으며 Chrome은 dist/를 로드한다. npm run dev는 변경 감시를 제공한다. 코어는 TypeScript에서 JavaScript·타입 선언을 생성한다. 실행 시 브라우저·번들러 의존성은 없다. 생성물은 제외하고 잠금 파일을 관리한다.

코어 테스트는 Node 기본 러너로 독립 실행한다. 기존 언어 동작·단락 평가·호스트 위임·취소·시간 제한·소스 위치를 검증한다. 확장은 빌드 산출물에서 옵션·테스트 탭·입력·커서·undo·취소를 검증하고 동기화·파일 호환 회귀도 유지한다.

## 후속 경고 분석

모듈화 이후 암시적 형변환 등의 경고 분석을 추가한다. 이번 진단 구조는 error/warning 심각도를 지원하고 warning은 실행을 막지 않는다. 실제 경고 규칙과 UI는 이번 범위 밖이다.
