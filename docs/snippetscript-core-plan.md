# SnippetScript 코어 분리 계획

## 목표와 순서

언어 분석·실행을 독립적인 TypeScript ES 모듈로 분리한다. Chrome과 향후 VS Code 등의 호스트가 같은 코어를 사용한다.

1. 현재 기능 변경과 이 계획을 커밋·푸시한다.
2. 확장 버전을 2.0.0으로 올리고 모듈화를 시작한다.
3. https://github.com/jiunkong/SnippetScript 를 language-core/ Git 서브모듈로 연결한다.
4. 공용 분석기·실행기와 브라우저 어댑터를 연결한다.
5. 회귀 검증과 개발 문서를 완료한다.

기존 변경은 보존하고, 코어는 독립적인 버전·커밋 이력을 갖는다. 확장은 특정 코어 커밋을 고정한다.

## 책임 경계

코어: 템플릿·표현식·중첩 fragment 분석, AST, 타입·연산자·내장 함수, 변수 스코프·분기·반복, 스니펫 호출, SnippetTemplate/SnippetFragment, 진단·토큰·참조, 시간·재귀 제한·취소.

확장: 트리거 매칭, DOM·선택·삽입·커서·undo, Chrome API, UI, 번역, 설정·동기화·파일 관리. 호출 인수 이름을 추출하는 문법은 코어에 둔다.

## 분석 API

```ts
const analysis = analyze(source, { library });
const result: SnippetFragment = await execute(analysis, {
  variables, library, host, signal, limits,
});
```

Analysis는 불변 SnippetTemplate(AST), 토큰, 진단, 스니펫 참조를 포함한다. 범위는 원본 UTF-16 [start,end)이며 줄 연결·중첩 리터럴에서도 유지한다. 표현식도 AST로 분석하며 실행 시 다시 파싱하지 않는다. fragment(string) 같은 새 소스만 추가 분석한다.

불완전한 입력에서도 가능한 토큰·진단을 반환한다. 오류 진단은 실행을 막는다. 본문과 라이브러리 변경 시 캐시를 갱신한다. 하이라이터와 테스트 탭은 같은 분석 경로를 사용한다.

토큰 종류: 구문 구분자, 키워드, 변수, 일반 내장 함수, 난수 함수, 타입 관련 함수, 스니펫 호출, 연산자, 리스트·인덱스 구두점, fragment 구분자, 커서 구분자·마커, 정규식·플래그, bool 리터럴(true/false), null 리터럴. 문자열·숫자 전용 강조 종류는 이번에 추가하지 않는다.

추가 구분: 일반 그룹 괄호는 `parenthesis`, `+ - * /`는 `arithmeticOperator`로 분리하고 확장에서 흰색으로 매핑한다. 함수 호출 괄호는 해당 함수 종류를 유지한다.

코어는 색상·CSS를 전달하지 않는다. 하이라이터가 종류를 CSS 클래스에 매핑한다. 표현식·커서·트리거 영역 배경은 구조 범위로 재현한다. 오류는 진단, 줄바꿈은 렌더링 옵션이다. 색상 커스터마이징 UI는 범위 밖이다.

## 실행과 호스트

```ts
host.invoke({ name, args, sourceRange }, { signal });
```

prompt/choice/toast/copy/paste/url/domain/title은 코어가 인수를 평가하고 호스트가 기능을 수행한다. 함수 명세(이름·인수·대기 정책)를 공유한다. 미지원 기능은 호출 시 구조화된 오류를 낸다. 시각·난수·UUID·스케줄러는 주입 가능하며 표준 JS 기본 구현을 제공한다.

코어가 시간·재귀 제한과 취소를 관리한다. 사용자 응답 대기는 제외하고 클립보드 대기는 포함한다. 취소 후 재개하지 않고 호스트에도 취소 신호를 전달한다. 오류에는 코드·인수·범위·호출 경로를 제공하고 호스트가 번역한다.

&&, ||, 삼항식은 선택된 분기만 실행한다. 나머지 타입·형변환·스코프·커서·fragment 동작은 현재와 동일하다. 문자열을 암묵적으로 실행 소스로 해석하지 않는다.

## 빌드와 검증

확장의 진입점과 의존 파일을 명시적인 ES 모듈로 전환하고 esbuild로 번들링한다. npm run build는 정적 파일·번들을 dist/에 모으며 Chrome은 dist/를 로드한다. npm run dev는 변경 감시를 제공한다. 코어는 TypeScript에서 JavaScript·타입 선언을 생성한다. 실행 시 브라우저·번들러 의존성은 없다. 생성물은 제외하고 잠금 파일을 관리한다.

코어 테스트는 Node 기본 러너로 독립 실행한다. 기존 언어 동작·단락 평가·호스트 위임·취소·시간 제한·소스 위치를 검증한다. 확장은 빌드 산출물에서 옵션·테스트 탭·입력·커서·undo·취소를 검증하고 동기화·파일 호환 회귀도 유지한다.

## 후속 경고 분석

모듈화 이후 암시적 형변환 등의 경고 분석을 추가한다. 이번 진단 구조는 error/warning 심각도를 지원하고 warning은 실행을 막지 않는다. 실제 경고 규칙과 UI는 이번 범위 밖이다.

## 트리거 분석 통합

`analyzeTrigger()`가 토큰·진단·매개변수 순서·정규식 패턴과 플래그를 제공한다. `snippetParameterNames()`와 `compileTrigger()`는 이 결과를 사용하며 확장의 `utils/triggers.js`에는 호환 어댑터만 둔다. 정규식 안의 `\{`·`\}`는 문자 중괄호로 보존하며, 반복 횟수와 문자 클래스의 중괄호도 구분한다. `${name}`의 기본 패턴은 `[^ ]+`이고 `${name:}`는 오류다.

## 문자열 이스케이프

일반 문자열 리터럴의 `\"`, `\'`, `\\`는 한 문자로, `\n`·`\t`는 줄바꿈·탭으로 디코딩한다. `\d` 등 미지정 이스케이프는 보존한다. 하이라이트·진단 범위는 원본 소스 기준을 유지한다.

문자열 내부에서 지원하는 이스케이프는 `stringEscape` 토큰으로 구분하고 확장에서 황금색으로 표시한다.


## 타입 진단 구현 현황

- 코어의 함수 명세에 매개변수 이름·허용 타입·가변 인수·대상별 타입 규칙을 정의했다.
- 기존 변수 타입 추론과 같은 AST 순회에서 함수 인수, 커서 표현식, 스니펫 커서 오프셋을 검사한다.
- 모든 가능 타입이 부적합하면 오류, 일부만 적합하거나 unknown이면 경고로 진단한다. any 매개변수는 모든 타입을 허용한다.
- 반복문 분석 중 수집한 타입을 합친 후 심각도를 판정한다. 오류와 경고 모두 원본 UTF-16 범위를 제공한다.
- 옵션 편집기는 오류를 빨간색, 경고를 노란색으로 표시하고 본문의 모든 진단을 나열한다. 경고는 실행을 막지 않는다.
- 일반 산술 연산의 암시적 형변환 진단은 아직 구현하지 않았다.

- 함수 인수 타입은 실행 시에도 같은 명세로 검사하며 암시적으로 변환하지 않는다. `join()`은 리스트 원소 타입도 검사한다. 문자열·fragment 대상의 `insertAt()` 삽입값은 문자열·fragment만 허용한다. 숫자 커서 오프셋도 문자열에서 자동 변환하지 않는다. 산술·조건식·본문 출력의 기존 규칙은 유지한다.

- 스니펫 호출 매개변수도 트리거 캡처와 같은 string으로 통일했다. 분석·실행·호출 시그니처에 적용하며 다른 타입은 str()로 명시적으로 변환해야 한다.

- 함수별 오버로드를 명세의 기준으로 삼아 타입 검사·반환 타입 추론·호출 후보·가이드 표가 공유한다. 작성 중인 호출도 이미 분석한 인수 타입으로 후보를 좁힌다. 함수 이름에 마우스를 올리면 툴팁이 나타나며, 이전·다음 화살표와 후보 번호를 제공한다. 입력이나 캐럿 이동으로 자동 표시하지 않는다.

## 함수 레지스트리 통합

- `language-core/src/functions.ts`의 각 함수 정의에 오버로드, 토큰 종류, 실행 핸들러, 추가 값 검증, 반환 타입 추론, 호스트 정책을 모았다.
- 실행기와 추론기는 함수 이름으로 분기하지 않고 등록된 핸들러와 명세를 사용한다. `fragment()`의 동적 실행, `random()`과 리스트 함수의 반환 타입 추론, 클립보드 실패 처리와 `toast()`의 undefined 반환도 각 정의에서 관리한다.
- 실행기는 호스트 호출과 fragment 실행을 공통 기능으로 제공하며, 브라우저 API 구현은 `content/browser-host.js`의 기능 테이블에 유지한다.
- 값 연산은 `value-operations.ts`로 분리해 함수 레지스트리와의 순환 의존을 방지하고, 기존 `values.ts`의 공개 API는 유지한다.
- 일반 코어 함수는 레지스트리에 정의 하나를 추가하면 분석·실행·툴팁·가이드에 반영된다. 새 브라우저 기능은 해당 호스트 구현도 필요하다.

## NaN 실행 오류

숫자 산술·단항 연산과 함수 반환값이 NaN이면 `err_number_nan` 오류를 낸다. 복합 대입과 동기 표현식 실행에도 같은 규칙을 적용한다. `num()`·`int()` 변환 실패를 0으로 바꾸거나, 반올림·최솟값·최댓값 함수에서 NaN을 대체·제외하던 처리를 제거했다. Infinity와 지연 평가 규칙은 유지한다.

## 0 제수 분석 오류

`/`·`%` 및 `/=`·`%=`에서 제수가 0인 숫자 상수식이면 분석 오류를 내고 제수 범위를 강조한다. `-0`과 `(1 - 1)`도 판별한다. 기존 AST의 숫자 상수 연산만 확인하며 변수 값이나 함수 호출을 실행하지 않는다. 다른 분석 오류와 마찬가지로 템플릿 실행을 막는다.
